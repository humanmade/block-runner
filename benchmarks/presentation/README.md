# Benchmark presentation

Public, screenshot-ready visualisations for the README and other collateral. One
self-contained `figures.html` + one lightweight `style.css` (Geist, no build, no
dependencies).

## View

Open `figures.html` directly, or serve the folder:

```sh
cd benchmarks/presentation && python3 -m http.server 8799
# http://localhost:8799/figures.html
```

Then screenshot each figure card (or the whole page) and drop the PNGs into the
main `README.md`.

## What's in it

1. **Models head-to-head** — paired bars: the same five models direct vs Block Runner.
2. **Complete current matrix** — all 11 comparable lanes, their scores, uplift, and evidence status.
3. **Measured Claude timing** — serial direct vs guided totals, with timing boundaries made explicit.
4. **How it works** — the conversion pipeline (input → translate → gate → media → blocks).
5. **The benchmark loop** — spec → producers → engine → scorer → log → reports, with the backtest loop.

Figures 1–3 are data-driven; 4–5 are static diagrams.

The generated `review.html` + `scoreboard.html` now live in this same folder
(gitignored, regenerated by `npm run bench`).

## Refreshing the data

The headline numbers are embedded in the `MODELS` constant in `figures.html`; the
same values are repeated in the adjacent matrix table. Reconcile them against the
current-suite rows in `benchmarks/results.jsonl`, versioned ratchet baselines, and
the run provenance before re-screenshotting. Timing values are transcribed from
`benchmarks/timings.jsonl`. Do not mix rows with different suite, scorer, prompt,
or runtime hashes.

Fonts are vendored in `fonts/` so the page renders identically offline.
