What the converter does

The converter reads authored HTML, maps it to Gutenberg blocks, validates and canonicalizes the blocks, replaces media URLs with attachment IDs, and serializes the final wp:* markup.

Every conversion runs through the Gutenberg validator. If a section cannot be represented as native blocks, Block Runner keeps that section as core/html and adds a warning with the source line.

How each benchmark score is produced

Each layout has a prompt and an expected block tree. Three source directories provide HTML. The selected engine converts each file, the scorer compares the result with the expected tree, and the script writes the scores and run metadata to disk.

The scorer does not call a model. A result records the test-set and scorer hashes used for that run. Compare two scores only when both hashes match. A backtest runs an older engine against the current test set and scorer.

Structure contributes 75% and content contributes 25%. Gutenberg validation failure halves the score. Each core/html fallback counts as a missed block. Coverage measures how much source text appears in the result.

Each direct score comes from one run. Block Runner scores come from saved per-section baselines; they are not averages of repeated runs. Terra and Sol used the previous guide, but their saved outputs were scored with the current test set and scorer. The rules engine runs locally without a model. Data is stored in benchmarks/results.jsonl, the baseline files, and the timing log.
